Chapter 3

Run your own (Hermes or OpenClaw)

Same shape: a gateway on a machine you control, a model you pick, then optional Telegram. Do not install both this weekend. Do not add cron until one chat works.

Pick one

Hermes Agent

From Nous Research (the lab behind the Hermes models — the agent is the app). CLI + desktop. Skills, memory, cron, a gateway to Telegram / Discord / Slack / WhatsApp / etc. Official docs: hermes-agent.nousresearch.com/docs.

OpenClaw

Open-source assistant + gateway. MIT. Stewarded by a nonprofit foundation (not an OpenAI product, even if OpenAI donates). WhatsApp, Telegram, Slack, Discord, Signal, iMessage… Official: openclaw.ai · docs at docs.openclaw.ai.

Both still need a brain. That’s usually a paid API or a subscription login, not a free magic local 7B that books flights. Local models need a huge context window for tool-calling — Hermes’s docs say 64K minimum or it refuses to start.

Path — Hermes (typical first self-host)

  1. Use the official path: Desktop installer on Mac/Windows from their site, or the install command on their quickstart. Read the script URL before you pipe it to bash.
  2. Run hermes setup (or Quick Setup / Nous Portal if you want the no-key OAuth path). Then hermes or hermes --tui.
  3. Ask something checkable: “What’s in this folder?” If that fails, stop. hermes doctor then hermes model. Do not add Telegram on a broken chat.
  4. Only then: hermes gateway setup for one channel. Allowlist your own user id.

Path — OpenClaw

  1. Download the app from openclaw.ai or follow their current install one-liner. They support Mac, Windows, Linux.
  2. Onboard until a Control UI chat replies. That’s the whole first win.
  3. Add one channel. Their docs talk about locking down who can DM the bot (allowFrom-style allowlists). Do that before you tell anyone the username.

Laptop closed = assistant dead unless you put the gateway on a VPS or a machine that stays on. That’s the whole “always-on” pitch. Don’t schedule a 7am briefing on a MacBook that sleeps.
