Chapter 4

Use it for code (without Cursor’s cloud)

You already have a local model from the last chapter. Now you point an editor at it. This will feel like a rougher Cursor — that’s the point of the experiment.

Do this only after Ollama works

If ollama run llama3.2 already chats, you’re ready. If not, go back. Don’t debug two new tools at once.

Pull a coding-flavored model if you have 16 GB RAM:

ollama pull qwen2.5-coder:7b

Smaller machine? Try qwen2.5-coder:1.5b for autocomplete only. Don’t expect it to rewrite a whole app.

Option 1 — Cline in VS Code (or Cursor)

Cline is an open-source agent extension. It can read files and propose edits. You can point it at Ollama instead of a paid API.

  1. Install VS Code if you don’t have it. (Cursor works too — you’re just swapping the brain.)
  2. Extensions: search Cline, install the official one.
  3. In Cline’s settings, set the provider to Ollama. Base URL is usually http://localhost:11434.
  4. Pick the model you pulled. Ask it to explain one file you already understand, so you can tell if it’s lying.

Option 2 — Aider in the terminal

Aider is a chat that edits your repo from the command line. Pair it with Ollama if you want local. Pair it with a paid API if you want it to actually finish the task.

Good first use: “explain this folder, don’t edit yet.” Then a tiny, safe edit on a copy of a project.

The Continue.dev footnote

You’ll see a hundred tutorials that say “install Continue + Ollama.” Continue was a popular open-source coding assistant. In 2026 it was acquired and the original repo went read-only. The last release can still work. It may not get fixes. If a tutorial from 2024 is your only map, prefer Cline or Aider instead.

Keep Cursor for the hard stuff. Local agents miss files, invent APIs, and stall. Use this path to learn the stack — not to finish a graded project the night before.
