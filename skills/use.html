Using skills

You can ask, or you can invoke.

Cursor finds skills when the app starts. Agent sees their names and descriptions, then decides if the current chat matches. You can also type / and pick the skill yourself.

Two ways a skill runs

Most skills can do both. Some are slash-only on purpose.

Agent decides

You talk normally. “Add a new artifact to the hub.” If a skill’s description matches, Agent can pull it in. This is the default.

You decide

In Agent chat, type /skill-name. That attaches the skill to that message. You can also attach one with @.

Keep it on for the whole chat. A skill used as a Custom Mode stays in context for the session. On a Mac that is Option+Enter after you select the skill. On Windows it is Alt+Enter. An active mode shows a badge on the chat input.

Where the files live

The folder that contains SKILL.md is the skill’s name. Parent folders are only for organizing.

Location Scope Good for
.cursor/skills/ in this repo This project Studio conventions everyone cloning the repo should get
~/.cursor/skills/ Your machine, all projects Personal taste that is not class-specific
.agents/skills/ and ~/.agents/skills/ Same idea, other agent roots Compatibility with the open Agent Skills layout

Do not put your skills in ~/.cursor/skills-cursor/. That folder is for Cursor’s built-in skills. Yours go in ~/.cursor/skills/ or the project’s .cursor/skills/.

Cursor also reads Claude and Codex skill folders if they exist. Nested .cursor/skills/ folders inside a monorepo are scoped to that part of the tree.

Give it a real job, or just talk

You can say “walk me through how you’d add another game” without actually adding one. Or use it next cycle when you ship something new.

Confirm it showed up

Open Customize in the sidebar and go to Skills. Project skills appear with the built-in ones. Cursor’s docs also mention them under Agent Decides with rules.

The fastest way to make a second one

Type /create-skill in Agent chat and describe the workflow. Cursor has a built-in skill that names the folder, writes SKILL.md, and asks where to save it.

Cloud Agents are picky about personal skills. Files in ~/.cursor/skills/ stay on your laptop until you turn on Sync Skills for Cloud Agents in Settings → Agents. Project skills in the repo travel with git. To share with a team, publish from Customize → Skills. That is different from sync.

Built-in skills you might already have

Cursor ships its own skills, including /create-skill, /create-rule, and others for automations, reviews, and settings. Type / in Agent chat to see the current list. Names can change as Cursor updates.

These are the ones people reach for constantly, because they are already installed. You do not write them. You just type the slash name.

Skill What people use it for
/create-skill Make a new skill without hand-writing the folder. This is the usual first one.
/create-rule Turn a short standing preference into a rule (taste, not a whole procedure).
/update-cursor-settings Change an editor setting when you cannot remember where it lives.
/canvas Build a live visual next to the chat: a table, a little tool, something to look at.
/review Have Agent pick a review pass instead of you prompting “please look this over” from scratch.
/review-bugbot Look for bugs and regressions. Paired with /review-security for a safety pass.
/split-to-prs Chop a huge change into smaller pull requests.
/loop Run a prompt or skill on a repeat (useful once you have a skill worth repeating).
/automate Set up a Cursor Automation from a schedule, Slack, GitHub, and similar triggers.
/migrate-to-skills Turn old Commands / some dynamic rules into skills if you had those already.

Also in the built-in set, if you need them: /create-hook, /create-subagent, /cursor-blame, /sdk, /shell, /statusline, /autopilot, /update-cli-config. Cursor can also auto-apply a built-in when your ask clearly matches it.

Homemade skills people write a lot look like: deploy to staging, write tests this repo’s way, draft the PR, apply a design system, convert critique notes, or land a page on a class hub. Design-look skills are in that pile too: “make the UI feel like X, not generic AI.” Official docs use deploy-app and file-scoped React patterns as the textbook examples. Full current built-in list is always behind / and on cursor.com/docs/skills.

Where to find existing skills

Cursor does not come with a giant public “design this site like a magazine” skill. Those live in plugins, GitHub folders, and other people’s laptops. This is the map of places. For named packs with install steps (Impeccable, frontend-design, and lists), go to Existing skills.

Already on your machine

Open Customize in the sidebar, then Skills. Built-ins, project skills, personal skills, and anything a plugin installed all show up here. Type / in Agent chat for the live menu.

Cursor Marketplace (official plugins)

Plugins can bundle skills. Browse cursor.com/marketplace, or search in Customize. Official listings are reviewed. Install, then check Skills again.

Community plugins

Cursor points community plugins and MCP servers at cursor.directory. Read what a plugin actually contains before you install it. Skills from a plugin appear in Customize next to yours.

GitHub: copy the folder

A skill is just a folder with SKILL.md. Copy it into .cursor/skills/name/ (this project) or ~/.cursor/skills/name/ (every project). Cursor also reads .claude/skills/, so a Claude skill folder often works as-is.

Places people browse

anthropics/skills includes the well-known frontend-design skill (distinctive UI, not generic AI look). Lists: awesome-agent-skills and awesome-frontend-skills. The open format lives at agentskills.io.

A friend, or a team

If someone says “I have a design skill,” ask them for the folder. Drop it in. On a Cursor Team plan they can also publish from Customize → Skills to a team marketplace, and you install it from there. That is different from syncing your personal skills to Cloud Agents.

Treat a stranger’s skill like a stranger’s script. Open SKILL.md before you trust it. Skills can tell Agent to run commands. Cursor’s official path for a whole GitHub repo is a plugin (the repo needs a marketplace/plugin manifest), then install from Customize. Copying one folder is the simple student version.
