Writing skills

One folder. One SKILL.md. A clear “when.”

If you remember nothing else: the description is how Agent decides this skill is relevant. Write what it does and when to use it, in words you would actually say in chat.

The file shape

YAML at the top, between three dashes. Then markdown instructions. The name must match the folder: lowercase letters, numbers, hyphens.

  • Required: name and description.
  • Optional: paths to limit which files wake it up.
  • Optional: disable-model-invocation: true if it should only run when you type /name.
SKILL.md
--- name: sounding-board-notes description: Turns critique into a talking page. Use when the user pastes desk-crit notes or wants a sounding-board writeup, not a pitch. ---   # Sounding-board notes   Keep their language. Do not invent a brand. Separate what was said from what you inferred.

What belongs in the body

Put in

The sequence. House style for this job. What to ask before guessing. Where files go. Examples of good vs bad output. Links to templates in the same skill folder.

Leave out

A second copy of the whole Cursor docs. Time-sensitive model names. Secrets. A novel. Cursor’s own guidance: keep the main file focused; park long reference material in a references/ file the agent can open only if needed.

Progressive disclosure. SKILL.md is the summary. Optional folders: scripts/ for commands the agent can run, references/ for deep notes, assets/ for templates. Point to them with relative paths.

A class-sized example you can copy

This is also saved as examples/class-cycle/SKILL.md in this artifact folder. Copy the folder into .cursor/skills/ or ~/.cursor/skills/ if you want it live. Do not drop it into skills-cursor.

examples/class-cycle/SKILL.md
--- name: class-cycle description: Helps pick and ship a small Learn, Vibe, Build cycle artifact. Use when the user mentions a studio cycle, weekly build, cycle check-in, or wants a small thing to make this week. ---   # Class cycle   1. Ask what they actually want to try, in one sentence 2. Keep the build static HTML, CSS, and a little JavaScript unless they ask otherwise 3. Match the hub pattern: own folder, README, tile on the root index 4. Do not delete earlier research or artifacts 5. Tell them how to open it with python3 serve.py on port 4321

The live skill already in this project is different on purpose: learn-vibe-artifact is the “add a tile the right way” playbook. class-cycle is the “what should we even make” playbook. You can have both.

Description tips that actually matter

Include trigger words

If you will type “cycle,” “desk crit,” or “degree audit,” those words should appear in the description. Agent matches on that text.

Say when not to use it

A line like “Not for one-line CSS tweaks” keeps the skill from jumping into every chat.

Keep the main file short

Long skills get skimmed. If you need a style bible, put it in references/ and tell the agent when to open it.

Ideas that are worth a skill in this class

These are the homemade kind. Cursor will not ship them for you. If you keep saying the same paragraph, save it. Broader buckets (voice, deploy, tests, review, and more) are on Genres.

Cycle / hub landing

You already have this one live: /learn-vibe-artifact. Same job as “put this on the shelf correctly.”

Desk-crit or sounding-board notes

Paste messy feedback. Keep your language. Do not lock a product. The Skill Builder has a starter for this.

Assignment in your voice

Turn research into the homework format without sounding like a brochure. Trigger words: “inspiration log,” “rewrite this,” “in my words.” This repo now has a live one: /rewrite-in-my-words.

Ship-check before you present

Hub tile, README, no broken links, theme is not a clone of the neighbor artifact, local server URL. A checklist skill, not a design opinion.

A website look

The friend version: “design this like a print magazine / brutalist poster / candy shop, and do not use generic AI UI.” Put type, color, spacing, motion, and anti-patterns in the skill. Scope it with paths to HTML and CSS if you only want it on UI files.

A tiny design system

CSS variables, type scale, how cards and buttons are built. Same idea as Cursor’s React-patterns example. Use it as a Custom Mode while you style a whole artifact.

Outside class, the hits are the same shape: deploy, tests, PR text, component conventions, a brand voice. If it is a pipeline, it is a skill. If it is a preference, it is a rule. Named packs: Existing skills.
