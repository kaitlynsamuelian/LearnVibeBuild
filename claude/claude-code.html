The "agentic loop"

Regular chat gives you one answer at a time. Claude Code instead works in a loop: it gathers context (reads your files), decides on a step, does it (edits a file or runs a command), looks at the result, and repeats — until your task is complete.

That's what "agentic" means: it can take a sequence of actions toward a goal, not just reply. You describe the destination; it figures out and takes the steps.

You stay in the loop too — Claude Code shows its steps and checks in with you, especially before anything risky.

the loop
1. 📖 Read relevant files (gather context)
2. 🧠 Decide the next step
3. ✏️ Edit a file / ▶️ run a command
4. 👀 Check the result
↻ Repeat until the task is done

What Claude Code can do

The everyday superpowers, in plain terms.

Edit your files

Create new files and change existing ones across your whole project — a small tweak or a big feature.

Run commands

Install tools, start your app, or run tests in the terminal — with your permission — and read the output.

Explore & explain

Understand an unfamiliar codebase, answer "where does X happen?", and explain code in beginner terms.

Fix bugs

Paste an error, and it investigates the cause, proposes a fix, and can verify the fix worked.

Work with Git

Write commit messages, create commits, open pull requests, and help you manage versions of your work.

Handle whole tasks

Given a goal like "add dark mode," it plans and carries out the many small steps to get there.

Permissions & staying safe

Claude Code asks before it acts — before editing files or running commands. You can approve once, deny, or say "always allow" for something you trust. This is your safety valve.

  • Read what it wants to do before saying yes.
  • Use Git so you can always undo changes.
  • Start small while you build trust in it.

There are faster, less-restricted modes for experienced users. As a beginner, keep the default "ask me" behavior on.

CLAUDE.md — your project's memory

CLAUDE.md is a plain text file you keep in your project. Think of it like a README written for Claude: it holds standing notes — how the project is organized, commands to run, your preferences and coding style.

Claude Code reads it automatically each session, so you don't have to repeat yourself. Want it to "always use British spelling" or "run the tests with npm test"? Write it once in CLAUDE.md.

You can even ask Claude Code to create or update its own CLAUDE.md for you: "set up a CLAUDE.md describing this project."

CLAUDE.md
# My Project   ## Commands - Start: npm run dev - Test: npm test   ## Style - Keep functions small - British spelling please

Slash commands

Type / in Claude Code to run a built-in shortcut. These control the session — no coding needed.

CommandWhat it does
/clearStart a fresh conversation with a clean slate (clears the context).
/compactSummarize the conversation so far to free up room while keeping the gist.
/modelSwitch which Claude model you're using (Sonnet, Opus, etc.).
/mcpView and manage connections to external tools (MCP servers).
/helpList available commands and get guidance.

You can also create your own custom commands, and the exact built-in list grows over time — type /help anytime to see what's available.

Skills

A Skill is a packaged set of instructions for doing a specific multi-step task a consistent way. Instead of re-explaining "how we write release notes" every time, you save it as a Skill and Claude uses it when relevant.

Skills are the modern, recommended way to package repeatable workflows. Beginners don't need to build any at first — just know they're how power users teach Claude their routines.

Subagents

A subagent is a helper Claude Code can spin up to handle a side task in its own separate workspace — while the main conversation keeps going. Great for parallel jobs like "go research how this library works and report back."

The subagent does its focused work independently and returns a summary, so the main agent (and you) don't lose your train of thought.

Think of subagents as assistants your assistant can hire for specific errands.

Main agent — building the feature
↳ Subagent — reading the docs
↳ Subagent — running the tests

Hooks & MCP — connecting Claude to your world

Two more words you'll hear. You don't need them to start, but here's what they mean.

Hooks

Automatic actions that fire at set moments in Claude Code's lifecycle — like "run the formatter every time a file is edited," or "run the tests after each change." They make behavior consistent and automatic, without you asking each time.

MCP (Model Context Protocol)

A standard way to plug Claude into outside systems — GitHub, a database, your browser, a design tool. Add one and Claude can use it as a tool. Think "apps for your agent." You add servers with claude mcp add.

MCP is shared across the AI world. The same MCP idea appears in other tools (including Cursor) — learn it once, use it everywhere.
